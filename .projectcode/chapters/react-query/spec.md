# react-query 서버 데이터를 TanStack Query로

종류: 리팩터
배울 것: useQuery, useMutation, 계층 queryKey, staleTime, invalidateQueries와 refetchType, setQueryData, gcTime, navigate의 replace, 로그아웃 때 캐시 비우기, Devtools

## 할 일
- S1 화면 아래 구석에 서버 데이터 도구(Devtools) 버튼이 생긴다. 누르면 받아 둔 데이터의 키 목록이 열린다
- S2 홈, 상세, 글 수정, 내 정보 화면이 받은 데이터를 캐시에 담아 그린다. 키는 목록 ["boards", "list"], 상세와 글 수정 ["boards", "detail", id], 내 정보 ["user"]다
- S3 받은 데이터는 1분 동안 fresh로 본다. 홈에서 상세로 갔다가 1분 안에 홈으로 돌아오면 목록 요청 없이 바로 그린다
- S4 상세에서 수정을 누르면 수정 화면이 상세와 같은 키의 캐시로 제목과 내용을 채운다. 상세 요청이 다시 가지 않는다
- S5 탭을 숨겼다 다시 보이면 받은 지 1분이 지난 화면 데이터만 다시 받는다. 1분 안이면 받지 않는다
- S6 글쓰기를 하면 목록을 즉시 다시 받고 끝난 뒤 홈으로 간다. 홈은 요청 없이 새 글을 맨 위에 보인다
- S7 글을 고치면 상세와 목록을 즉시 다시 받는다. 상세를 받은 뒤 상세로 가고 요청 없이 바뀐 제목을 보인다. 1분 안에 홈에 가면 요청 없이 바뀐 제목이 보인다
- S8 글을 지우면 목록을 즉시 다시 받고 끝난 뒤 홈으로 간다. 지운 글은 잠깐도 보이지 않는다. 방문 기록에서 지운 글 주소가 홈으로 바뀌어 뒤로 가기로 지운 글에 가지 않는다
- S9 댓글을 쓰거나 지우면 그 글 상세만 즉시 다시 받아 댓글이 바로 붙고 지워진다. 목록 요청은 가지 않는다
- S10 내 정보를 고치면 응답으로 캐시를 채우고 홈으로 간다. 내 정보 요청은 다시 가지 않는다. 1분 안에 다시 들어오면 요청 없이 바뀐 이메일이 보인다
- S11 로그아웃하면 캐시를 비운다. ssar로 내 정보를 본 뒤 로그아웃하고 cos로 로그인해 1분 안에 내 정보에 들어가도 cos@nate.com이 보인다

## 캐시 갱신 전략
- 글을 쓰거나 고치거나 지우면 목록을 즉시 다시 받는다. 목록은 가장 많이 가는 화면이라 그 요청은 곧 어차피 간다. 미루면 홈에서 옛 목록이 먼저 보였다가 바뀐다
- 응답이 캐시의 데이터와 모양이 같으면 응답으로 캐시를 채운다. 요청이 하나 준다
- 응답이 일부뿐이면 무효화해 서버에서 다시 받는다. 서버 값이 늘 맞다
- 쓰기 뒤 바로 갈 화면의 데이터는 즉시 받고 끝난 뒤 이동한다. stale 데이터는 먼저 보이기 때문에 기다리지 않으면 옛 값이 잠깐 보인다
- 없어진 데이터는 방문 기록에서 지워 다시 갈 길을 막는다. 볼 화면이 없는 캐시는 gcTime 5분 뒤 저절로 사라진다

| 쓰기 | 응답 | 처리 | 이유 |
|---|---|---|---|
| 글쓰기 | 글 하나 (id, title, content) | 목록 무효화. 즉시 받고 기다린 뒤 홈으로 | 목록 순서와 개수는 서버가 정한다 |
| 글 수정 | 글 일부 (id, title, content) | 상세와 목록 무효화. 둘 다 즉시 받음. 상세를 받은 뒤 상세로 | 상세에는 작성자, owner, 댓글이 더 있다 |
| 글 삭제 | 없음 | 목록 무효화. 즉시 받고 기다린 뒤 지운 글 주소를 홈으로 바꿔 이동. 상세 캐시는 그대로 둠 | 지운 글로 돌아갈 길이 없어 상세 캐시는 저절로 사라진다 |
| 댓글 쓰기, 삭제 | 댓글 하나, 없음 | 상세 무효화. 보고 있어 즉시 받음 | 목록에는 댓글이 없다. 댓글 순서와 owner는 서버가 정한다 |
| 내 정보 수정 | 내 정보 전체 (id, username, email) | 응답으로 캐시를 채움 | 조회 응답과 모양이 같다 |

탭이 다시 보일 때는 기본 동작을 그대로 쓰고 코드에는 주석으로 적는다.
지금 화면의 stale 데이터만 다시 받는다.
staleTime이 1분이라 받은 지 1분 안에는 요청이 가지 않는다.

## 흐름
화면에 들어감 -> fresh 캐시가 있으면 바로 그림, stale이면 먼저 그리고 다시 받음, 없으면 받음 -> 쓰기 요청 -> 전략대로 캐시 처리 -> 이동 -> 로그아웃하면 캐시 비움

## 시나리오
서버를 시드 상태로 띄우고 Devtools와 브라우저 네트워크 탭을 열어 둔다.

### 1 캐시로 바로 그리기
- 홈에 들어가면 ["boards", "list"]가 fresh로 생긴다
- 제목1 상세에 갔다가 1분 안에 홈을 누르면 목록 요청이 가지 않는다
- 상세에서 수정을 누르면 상세 요청이 가지 않고 제목과 내용이 채워진다

### 2 탭이 다시 보일 때
- 홈에 들어가고 1분 안에 다른 탭에 갔다 돌아오면 요청이 가지 않는다
- 1분이 지난 뒤 다른 탭에 갔다 돌아오면 목록 요청이 한 번 간다

### 3 글쓰기
- ssar로 로그인해 홈을 본 뒤 글쓰기에서 새 글을 쓴다
- 목록 요청이 끝난 뒤 홈으로 가고 새 글이 처음부터 맨 위에 있다
- 홈에 온 뒤에는 목록 요청이 다시 가지 않는다

### 4 글 수정
- ssar로 홈과 제목1 상세를 본 뒤 제목을 고친다
- 상세와 목록 요청이 바로 가고, 상세를 받은 뒤 상세로 간다
- 바뀐 제목이 처음부터 보인다
- 1분 안에 홈을 누르면 목록 요청이 가지 않고 바뀐 제목이 보인다

### 5 글 삭제
- ssar로 홈과 제목2 상세를 본 뒤 삭제를 누른다
- 목록 요청이 끝난 뒤 홈으로 가고 제목2가 처음부터 없다
- 뒤로 가기를 눌러도 제목2 상세로 가지 않는다
- Devtools에서 ["boards", "detail", "2"]는 inactive로 남았다가 5분 뒤 사라진다

### 6 댓글
- ssar로 제목1 상세에서 댓글을 쓰면 상세 요청만 가고 댓글이 붙는다
- 그 댓글을 지우면 상세 요청만 가고 댓글이 빠진다

### 7 내 정보
- ssar로 내 정보에서 이메일을 바꾸고 수정하기를 누른다
- 내 정보 요청이 다시 가지 않고 홈으로 간다
- 1분 안에 내 정보에 다시 들어가면 요청 없이 바뀐 이메일이 보인다

### 8 로그아웃
- ssar로 내 정보를 본 뒤 로그아웃하면 Devtools의 키가 모두 사라진다
- cos로 로그인해 내 정보에 들어가면 cos@nate.com이 보인다

## 그대로인 것
- 서버 데이터 도구 버튼 말고는 모든 화면의 모습이 같다
- 데이터를 받기 전에는 지금처럼 내용이 비어 있다
- 회원가입과 로그인은 지금처럼 바로 요청한다
- 앞 장 테스트가 그대로 통과한다

## 안 하는 것
- 받는 동안 로딩 표시: error-handling 장
- 요청 실패와 없는 글 안내: error-handling 장
- 실패한 요청 다시 시도 횟수: error-handling 장
- 버튼 중복 클릭 막기: 미룸
- 회원가입과 로그인 요청 바꾸기: 안 만듦
- 글 상세 미리 받기: 안 만듦
- 낙관적 업데이트: 안 만듦
