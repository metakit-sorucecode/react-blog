# reply 댓글 쓰기와 삭제

종류: 기능
배울 것: 요청 뒤 상세 다시 불러오기

## 할 일
- S1 상세에서 owner가 true인 댓글에만 휴지통 버튼이 보인다. ssar로 로그인하면 /board/4의 댓글1, 댓글2에는 보이고 댓글3에는 보이지 않는다. 로그인 전에는 어느 댓글에도 보이지 않는다
- S2 댓글 입력칸에 쓰면 화면이 쓴 값을 기억한다
- S3 등록을 누르면 글 번호와 댓글을 서버에 보내고 상세를 다시 받는다. 댓글 목록 끝에 ssar와 새 댓글이 보인다
- S4 등록이 끝나면 댓글 입력칸이 빈다
- S5 휴지통을 누르면 서버에서 그 댓글을 지우고 상세를 다시 받는다. 목록에서 그 댓글이 사라진다

## 요청과 응답
POST /api/replies
요청 헤더: Authorization: Bearer eyJhbGciOi...
요청: { "boardId": "4", "comment": "새 댓글" }
응답 body: { "id": 4, "comment": "새 댓글", "userId": 1, "username": "ssar", "owner": true }

DELETE /api/replies/:id
요청 헤더: Authorization: Bearer eyJhbGciOi...
응답 body: null

## 흐름
쓰기: 상세 -> 댓글 입력 -> 등록 클릭 -> 서버에 댓글 저장 -> 상세 다시 받음 -> 목록 끝에 새 댓글 -> 입력칸 비움
삭제: 상세 -> 내 댓글 휴지통 클릭 -> 서버에서 댓글 삭제 -> 상세 다시 받음 -> 목록에서 그 댓글 사라짐

## 그대로인 것
- 상세의 제목, 작성자, 내용, 글 수정과 삭제 버튼은 바뀌지 않는다
- 목록, 글쓰기, 글 수정, 회원가입, 로그인의 동작과 모습은 바뀌지 않는다

## 안 하는 것
- 댓글 삭제 전 확인 창: 미룸
- 빈 댓글 막기: form-hook 장
- 로그인 전 댓글 입력 자리에 로그인 안내: auth-guard 장
- 댓글 쓰기와 삭제 실패 안내: error-handling 장
- 버튼 중복 클릭 막기: 미룸
- 댓글이 없을 때 안내: 안 만듦
