# form-hook 폼을 react-hook-form으로

종류: 리팩터
배울 것: register, handleSubmit, reset, 검사 규칙 하나와 errors 문구, mode로 칠 때마다 검사

## 할 일
- S1 회원가입에서 아이디, 비밀번호, 이메일을 넣고 가입하기를 누르면 가입 완료 알림 뒤 로그인 화면으로 간다
- S2 로그인에서 아이디와 비밀번호를 넣고 로그인을 누르면 헤더 메뉴가 바뀌고 홈으로 간다
- S3 글쓰기에서 제목과 내용을 넣고 글쓰기를 누르면 홈 맨 위에 새 글이 보인다
- S4 글 수정 화면은 기존 제목과 내용을 채워 보인다. 고쳐서 수정하기를 누르면 상세에 바뀐 제목이 보인다
- S5 상세에서 댓글을 넣고 등록을 누르면 댓글이 붙고 입력칸이 빈다
- S6 내 정보 화면은 아이디(읽기만)와 이메일을 채우고 새 비밀번호는 비워 둔다. 이메일을 고쳐 수정하기를 누르면 홈으로 가고 다시 들어오면 바뀐 이메일이 보인다
- S7 회원가입 비밀번호는 칠 때마다 검사한다. 1자에서 3자면 비밀번호 칸 아래에 빨간 글자로 "비밀번호는 4자 이상이어야 합니다"가 보이고 4자가 되면 문구가 사라진다
- S8 비밀번호가 3자인 채 가입하기를 누르면 요청을 보내지 않고 비밀번호 칸에 커서가 간다
- S9 비밀번호 칸이 비어 있으면 이 규칙은 검사하지 않는다. 지금처럼 서버가 막고 "입력값이 필요합니다" 토스트가 뜬다

## 흐름
입력 -> 칠 때마다 규칙 검사 -> 틀리면 입력 아래 문구, 누르면 요청 없이 그 칸으로 커서 -> 맞으면 요청 -> 지금처럼 이동

## 그대로인 것
- 비밀번호 규칙 말고는 모든 폼의 모습과 동작이 같다
- 로딩 표시와 실패 토스트는 그대로다
- 앞 장 테스트가 그대로 통과한다

## 안 하는 것
- 서버가 돌려준 실패를 입력 아래 문구로 보이기: 안 만듦. 토스트로 보인다
- 다른 칸의 검사 규칙(빈 칸, 이메일 모양 등): 안 만듦. 규칙은 하나만 둔다
- 공백만 입력한 값 막기: 미룸
- 버튼 중복 클릭 막기: 미룸
- zod 스키마 검사: 안 만듦
